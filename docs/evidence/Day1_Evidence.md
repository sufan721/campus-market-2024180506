### 1.2 项目背景理解

**为什么要开发校园轻集市？**
- 校园内存在大量闲置物品流转需求（教材、电子产品、生活用品等）
- 传统的 QQ 群、微信群交易存在信息零散、检索困难、信任缺失等问题
- 通过开发一个轻量级校园交易平台，将前端工程化知识应用于真实场景

**系统主要解决的实际问题：**
1. 校园二手物品信息集中发布与浏览
2. 商品分类检索，快速找到所需物品
3. 买卖双方的安全沟通渠道
4. 交易状态的可追踪管理
5. 降低校园闲置物品流转的交易成本

**系统包含的业务场景：**
1. 游客浏览商品列表
2. 用户注册与登录
3. 卖家发布商品信息
4. 买家搜索与筛选商品
5. 商品详情查看
6. 买卖双方在线沟通
7. 商品收藏管理
8. 个人中心信息维护

**七天实训的最终目标：**
完成一个功能完整的校园轻集市前端应用，掌握 Vue 3 工程化开发、Git 版本管理、AI 协作开发、软件工程规范，并通过过程性证据记录完整的开发过程。

### 1.4 核心代码阅读

**main.ts 分析：**

```typescript
// Vue 3 应用的标准创建流程
import { createApp } from 'vue'        // ① 导入应用创建函数
import { createPinia } from 'pinia'    // ② 导入状态管理创建函数

import App from './App.vue'            // ③ 导入根组件
import router from './router'          // ④ 导入路由配置

const app = createApp(App)             // ⑤ 创建 Vue 应用实例
app.use(createPinia())                 // ⑥ 注册 Pinia 插件
app.use(router)                        // ⑦ 注册 Router 插件
app.mount('#app')                      // ⑧ 挂载到 DOM
```

**关键理解：**
- `createApp(App)` — Vue 3 的显式应用创建方式，区别于 Vue 2 的 `new Vue()`
- `.use()` — Vue 的插件注册机制，Pinia 和 Router 都以插件形式集成
- `'#app'` — 对应 `index.html` 中的挂载点，是整个 Vue 应用的 DOM 入口

**router/index.ts 分析：**

Router 的作用是 **URL 到组件的映射**：
1. 定义 URL 路径与页面组件的对应关系
2. `<RouterView />` 作为动态渲染出口
3. 支持页面间无刷新切换（SPA 核心能力）
4. 首页能显示是因为 `/` 路径映射到 `HomeView` 组件

**App.vue 分析：**

`App.vue` 是项目的**根组件**，作用相当于整个应用的"布局骨架"：
- 它提供了全局的 HTML 结构（标题、容器）
- `<RouterView />` 是动态内容区域——不同路由对应不同页面内容
- 所有页面都在 `App.vue` 的框架内渲染

## 六、实验思考

### 6.1 为什么课程没有要求第一天立即开发页面？

第一天不写代码，而是**建立对项目的整体认知**。这体现了软件工程中的"慢即是快"原则：

1. **理解需求是第一位的** — 如果连要做什么都不清楚，写出的代码大概率需要返工
2. **熟悉项目结构** — 理解目录分工后，后续开发时才知道代码应该放在哪里
3. **建立技术认知** — 理解 Vue 3 的启动流程、路由原理，后续开发才能得心应手
4. **培养工程习惯** — 文档阅读、环境配置、过程记录这些"软技能"和写代码同样重要

就像盖房子需要先看图纸、打地基，而不是上来就砌墙。

### 6.2 软件工程中的"理解项目"为什么比"开始编码"更重要？

1. **避免方向性错误** — 理解错了需求，写再多代码也是浪费
2. **提高开发效率** — 熟悉项目结构后，能快速定位到正确的文件进行修改
3. **减少返工成本** — 软件工程中，修复一个需求阶段引入的错误，成本是编码阶段的 10~100 倍
4. **团队协作需要** — 在真实项目中，不理解项目就动手会影响整个团队的进度
5. **代码质量的基础** — 理解项目架构和规范，才能写出风格一致的高质量代码

**结论：** "先理解，后行动"是软件工程的基本原则。编码只是软件开发的一小部分，理解需求、设计架构、规划任务同样重要。

### 6.3 AI 在软件开发中应该承担什么角色？

通过今天的实践，我认为 AI 应该承担以下角色：

| 角色 | 说明 |
|------|------|
| **代码解释器** | 快速解释不熟悉的代码逻辑和框架机制 |
| **知识加速器** | 快速查询技术细节，减少查文档的时间 |
| **代码生成助手** | 在明确需求后，辅助生成样板代码 |
| **审查建议者** | 提供代码改进建议，但最终决策权在人 |

AI **不应该**承担的角色：
- ❌ **决策者** — AI 不了解项目的完整上下文和业务约束
- ❌ **责任承担者** — AI 生成的代码需要人来验证和负责
- ❌ **需求分析师** — AI 无法替代与真实用户的沟通

**核心认知：** AI 是**协作伙伴**，不是**替代者**。人是驾驶员，AI 是导航仪——导航仪可以指路，但方向盘必须掌握在自己手中。

### 6.4 今天最大的收获是什么？

今天最大的收获不是某个具体的技术知识点，而是一个**认知上的转变**：

> **软件开发 ≠ 写代码**

以前我总觉得"学会开发 = 学会写代码"，但 Day 1 的经历让我意识到：

- 阅读文档、理解需求、分析架构、规划任务——这些"不写代码"的环节同样是软件开发的核心组成部分
- 一个好的开发者不仅是"能写代码的人"，更是"能理解问题并找到正确解决方案的人"
- AI 可以帮我们写代码，但**理解为什么这样写、判断这样写对不对**的能力，才是开发者的核心竞争力

这个认知将成为我后续 6 天学习和未来职业发展的基础。
